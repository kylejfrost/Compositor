# Compositor project format, versions 1–13

A `.comp` file is a macOS document package containing `manifest.json`, an `images/` directory of `<layer UUID>.png` assets, for documents opened from Photoshop a `psd/` directory of sidecars and a `smartobjects/` directory of smart-object contents (version 10), and, for documents with Profile adjustments, a `profiles/` directory (version 10). Saves made through the app or its document save tool may also include `QuickLook/Preview.jpg`, a flattened preview that loading ignores.

The manifest identifies `com.compositor.project`, version `13` for new saves (versions `1`–`12` remain readable), and the sRGB working space. It stores document UUID, pixel dimensions, active layer UUID, and layers in bottom-to-top order. Each layer stores its UUID, name, visibility, transform (origin, size, clockwise rotation, flips, sampling), and optional image filename. Blank layers have no image asset.

Embedded PNGs preserve source pixels and transparency; transforms remain separate. Projects survive moving or deleting imported source photos. Saving uses a coordinated atomic package replacement. Unsupported versions, invalid metadata, missing assets, unsafe paths, and oversized data are rejected before replacing the live document.

Limits (`DocumentLimits`): 30,000 pixels per canvas/image side; the layers' source pixels together within the document pixel budget, which scales with the Mac's memory (a quarter of it at 4 bytes a pixel, from 200 to 800 million pixels), so a project saved on a larger Mac can be too large to open on a smaller one; 10,000 layers, 4 MiB manifest, 512 MiB per encoded asset. See `ProjectStore.swift` for validation.

Undo history and viewport are session-only. Opening fits the canvas, restores selection, and starts with clean history. Future editable features must extend the schema and round-trip tests. PNG export is a flattened derivative and does not mark project edits saved.

Image Size adds optional `resolution` (pixels/inch, 1–9600). Older manifests without it default to 72. This additive field retains version 1 compatibility. Both PNG and JPEG exports include document resolution metadata. Resampling stores the new layer pixels and bounds; undo retains the prior sources only during the current session.

Version 2 adds optional `parentID` and `isGroup` on layer records. A group has no image file. Root nodes have no parent; children refer to an existing group. Array order defines bottom-to-top sibling order; renderers traverse each group as a contiguous subtree. Visibility is inherited without changing child flags. Cycles, missing/non-group parents, image-bearing groups, and nesting beyond 64 ancestor levels are rejected. Group ancestors permit room for leaf nodes at the deepest level. Group metadata survives image/canvas resizing and cropping. Older app builds reject version 2 rather than misrender grouped documents. Collapse state is not serialized.

Version 3 adds optional per-layer `opacity` (finite 0–1) and `blendMode` (Normal, Multiply, Screen, Overlay, Darken, Lighten, Difference, Color Dodge, Color Burn). Missing fields default to full opacity and Normal. Group records required those defaults until version 8, which lets a folder carry its own opacity; a folder's opacity multiplies into every layer inside it, while its blend mode stays Normal because folders are pass-through. Effects are applied during compositing and retained as metadata when resizing sources. Files declaring older versions cannot contain non-default appearance values.

Version 4 adds optional `maskFile` and `maskEnabled` fields to individual layers. Mask filenames must be `<layer UUID>.mask.png` under `images/`; enabled defaults to true when a mask exists. Records without masks omit both fields. Groups cannot carry masks in this version. Files declaring versions 1–3 cannot contain mask metadata.

Masks store 8-bit grayscale coverage without alpha (white reveals, black hides). Their normalized extent matches the image’s local rectangle, so the same layer transform applies to both. A uniform 1×1 mask is valid and avoids allocating full-resolution pixels before painting. Nonuniform mask pixels and a thumbnail are immutable assets shared by history. Image Size resamples them with the image transform; Canvas Size and Crop preserve their pixels. Masks may store as many pixels again as the layers' budget allows, counted on their own; per-side and per-file limits also apply to masks. Disabled masks remain embedded and editable but do not affect compositing. Image-versus-mask target selection is session-only and reopens on image pixels.

Version 5 adds optional `maskSourceID`: the UUID of a non-group layer supplying live alpha in document coordinates. It multiplies the target’s alpha alongside its enabled raster mask. Source pixels, transform, opacity, raster mask and upstream live masks contribute coverage; visibility and RGB color do not. Sources remain independent layers. Missing references, self-links, cycles, group endpoints and chains over 256 nodes are rejected. Deletion can bake the live coverage into dependent image pixels (retaining their raster masks) or remove the links, as one undoable operation. Links survive image/canvas resize and crop. Older versions default to no live mask; older app builds reject v5.

UI terminology: these alpha links are clipping masks. Option-click assigns the lower sibling’s base or releases the connection. Multiple clipped layers share one base, show indented above it, and release when moved outside the contiguous stack. The underlying `maskSourceID` representation is unchanged.

Version 6 allows `maskFile` and `maskEnabled` on group records. A folder has no image, so its mask covers the folder's own transform rectangle (the canvas size when the folder was created); Image Size resamples it through that transform, and Canvas Size and Crop preserve its pixels, exactly as for layer masks. Groups are pass-through, so an enabled folder mask multiplies the coverage of every descendant layer, together with that layer's own mask and any enclosing folders' masks; clipping-mask coverage is unaffected. Files declaring versions 1–5 cannot give a group a mask, and older app builds reject v6.

Version 7 adds adjustment layers: a layer record with an optional `adjustment` object and no `imageFile`. Adjustment layers cannot be groups and cannot carry `text`; like any layer they take a transform, opacity, blend mode, raster mask and clipping link, and they affect everything composited below them within their folder. `kind` is one of `Hue/Saturation`, `Levels`, `Curves`, `Exposure`, `Gradient Map`, `Grain`, `Invert`, `Black & White` and `Color Balance` (version 9 adds three more). The record carries the settings of every kind, each optional and defaulting to an identity adjustment: `hue` (±360), `saturation` and `lightness` (±100), `colorize` and `hsvSettings` for Hue/Saturation; `levels` (four channel ranges, RGB then red, green, blue); `curves` (four channel point lists); `exposureSettings`; `gradientMapSettings` (`shadows`, `highlights`, `reversed`); `grainSettings`; `blackWhiteSettings`; `colorBalanceSettings`. Out-of-range or non-finite values are rejected. Files declaring versions 1–6 cannot contain adjustment records, and older app builds reject v7. See `LayerAdjustment.swift` for the exact ranges.

Version 8 lets a folder carry its own `opacity`, which multiplies into every layer inside it; a folder's blend mode stays Normal because folders are pass-through (files declaring 1–7 require folders at full opacity). It also adds an optional top-level `guides` array of alignment guides, each with `id`, `axis` (`horizontal` or `vertical`) and `position` in document pixels (finite, at most 1,000,000 in magnitude). At most 1,000 guides are stored; files declaring 1–7 cannot contain guides. Guides survive Canvas Size and Crop by offsetting with the canvas.

Version 9 adds three adjustment kinds that sample neighboring pixels: `Gaussian Blur` (`blurRadius`, 0.1–250 document pixels), `Motion Blur` (`motionAngle`, −90 to 90 degrees, and `motionDistance`, 1–2000) and `Add Noise` (`noiseAmount`, 0.1–400, `noiseGaussian`, `noiseMonochromatic` and `noiseSeed`, so the pattern is stable between sessions). Files declaring 1–8 cannot contain these kinds; the earlier adjustment kinds remain valid at version 7 and up.

Version 10 lets a text layer color some of its letters differently: optional `colorRuns` in its `text` metadata (see Editable text). Files declaring 1–9 cannot contain it. Version 10 also holds Photoshop data, locks and fill, and Profile adjustments (see [Version 10: Photoshop data, locks and fill](#version-10-photoshop-data-locks-and-fill) and [Profile adjustments](#profile-adjustments-version-10)); these were added alongside `colorRuns` under the same number, all optional, so a version 10 file may carry any of them.

Version 11 lets those letters use different faces too: optional `fontRuns` in the same metadata. Files declaring 1–10 cannot contain it. `colorRuns` stays valid from version 10.

Version 12 marks the first project version written by the MCP and Photoshop integration. It establishes that readers understand the PSD preservation sidecars, locks, Fill, smart-object payloads, and profile adjustments used by this build. Files declaring versions 1–11 remain readable and preserve the optional values their version carries; versions 10 and 11 can occur in projects written by the earlier feature branch. Builds that support only through version 11 must refuse version 12 rather than silently dropping Photoshop-specific state.

Version 13 adds optional `sizeRuns` to editable text, the per-letter font sizes used by imported Photoshop type layers and MCP text edits. Each run has a UTF-16 `location`, positive `length`, and `fontSize` in layer pixels (1–2,000). Runs are sorted, non-overlapping and contained in the text. Files declaring versions 1–12 cannot contain size runs.

### Additive layer fields

Later fields are optional and not gated on the version, so older readers ignore them and keep the pixels or the linked mask as they were:

- `maskPlacement` and `maskLinked`: an unlinked mask (`maskLinked` false; missing means linked) keeps its own transform in `maskPlacement`, a document-space rectangle like the layer transform, and no longer follows the layer when it moves. Both require a `maskFile`.
- `shape`: a layer made with the Shape tool keeps its style (`kind`, `red`/`green`/`blue`, `cornerRadius` in document pixels, and for lines `lineWidth` plus `start` and `end` as fractions of the layer box) so it redraws cleanly when scaled. Its PNG is still an ordinary raster; once anything else changes those pixels the metadata is dropped.

### Editable text

Pixel layer records may include optional `text` metadata: content, PostScript font name, font size in pixels, RGB color, alignment, tracking, line spacing, optional `boxSize` paragraph bounds and optional `horizontalScale` (finite 0.1–10; missing means 1). Text wraps inside these bounds; changing them reflows the text without scaling the font. The PNG remains the display and export fallback. Older readers ignore this metadata. Transforms, duplication, masks and canvas-size changes preserve it; destructive pixel operations rasterize text and omit the metadata on the next save. Photoshop type layers import as editable text whose PNG remains Photoshop's own raster until edited. Missing fonts are substituted when edited using the closest installed family member, then Helvetica Neue or Times New Roman, then the system font. From version 10, optional `colorRuns` lists letters painted in another color than the text's own `red`/`green`/`blue`: each run has `location` and `length` in UTF-16 units of the content, plus `red`, `green` and `blue` (0–1). From version 11, optional `fontRuns` lists letters set in another face than `fontName`: the same `location` and `length`, plus `fontName`. Runs of either kind are sorted, do not overlap, have a positive length and end within the content; letters outside every run use the text's color or face.

### Layer effects

An optional `effects` record contains independent `stroke`, `shadow`, `colorOverlay`, `innerShadow`, `outerGlow` and `innerGlow` records. Stroke carries a size (0–500 layer pixels), a color, an opacity and an `inside` flag choosing which side of the edge it sits on; drop shadow and inner shadow each carry an angle, a distance, a blur, a color and an opacity, and drop shadow an optional `knocksOut` flag (Photoshop's "Layer Knocks Out Drop Shadow"; missing means on, so the layer's own shape hides the shadow beneath it even at a low Fill, and only an imported Photoshop file sets it to false); color overlay carries a color and an opacity; outer glow and inner glow each carry a size (0–500 layer pixels), a color and an opacity. Each supports optional `enabled` visibility (missing means visible); hidden effects keep all parameters and remain listed under their layer. Effects, including their visibility, are saved and participate in document undo. Canvas previews run on a serial background worker with a shared pixel budget; exports render the full-resolution effects. A record omitting an effect means that layer does not have it, so older readers see the effects they understand and ignore the rest.

### Version 10: Photoshop data, locks and fill

Version 10 keeps what a Photoshop file holds beyond Compositor's own model, so a document opened from a PSD can be saved as a project and written back to Photoshop with every feature intact. Older app builds reject v10, and files declaring versions 1–9 cannot contain any of these fields (`locks`, `fillOpacity`, `psd`, a shape's `stroke`).

- **Locks.** Optional layer `locks`: Photoshop's `lspf` bits as an unsigned 32-bit number — `0x01` transparency, `0x02` pixels, `0x04` position, `0x08` artboard nesting, `0x80000000` lock all (which implies the others). Every bit is kept, known or not, so a file's value comes back out unchanged. Missing means unlocked.
- **Fill.** Optional layer `fillOpacity` (finite 0–1, Photoshop's Fill): it dims the layer's pixels but not its effects. It is stored apart from `opacity`, which dims both. Missing means 1.
- **Shape strokes.** A shape layer's `shape` record (the shape drawn again whenever the layer is resized) may carry `stroke`, Photoshop's shape stroke: `enabled`, `width` (finite 0–500 document pixels), `red`, `green` and `blue` (0–1) and `alignment` (`center`, `inside` or `outside` the shape's edge). The layer's pixels hold the stroke too: the shape sits inset from the layer's edges by how far the stroke reaches past it (half the width centered, all of it outside, none inside). A disabled stroke keeps its settings and isn't drawn. On a line the stroke is the line's own color, so it draws the line wider. Image Size scales the width with the corner radius and line width; a result over 500 pixels leaves the layer as its resampled pixels. Missing means no stroke; `importedShape` carries the stroke as imported.
- **Layer Photoshop data.** Optional layer `psd` record. It holds:
  - the record fields as read: the four-character `blendKey`, including modes Compositor lacks; `flags`, `clippingByte` and `fillerByte`; `maskFlags`, `maskDefaultColor` and `maskParameters`; `layerID` (`lyid`); `colorLabel` (`lclr`); `nameSource` (`lnsr`); `importedName`
  - `clippingByte` drops to 0 when Compositor releases a clip it modeled: the layer is moved out of its clipping group, its base is deleted, Release Clipping Mask is used, or it is copied into another project. So a nonzero byte on a layer without `maskSourceID` is a clip the importer couldn't model, to a folder, an adjustment or a placeholder. A PSD writer keeps that byte only while the nearest unclipped record below the layer is still one of those.
  - `textIndex`, a type layer's `TySh` `TextIndex` (a signed 32-bit number: which of the document's `Txt2` texts is the layer's), kept even when the rest of its type data can't be read; and `isBackground`, `true` on Photoshop's Background layer (`lnsr` `bgnd` with no transparency channel). Missing means none and `false`.
  - `importedMaskRect`, on a layer whose Photoshop mask was padded on import: `[[x, y], [width, height]]` (finite, none negative), where the rectangle Photoshop stored the mask in lies within the layer mask's own pixels. Photoshop trims a mask to what differs from its default color (`maskDefaultColor`) and shows that color everywhere else, so import pads the mask with it to cover the layer too (a folder's or adjustment layer's mask, the canvas). The mask then covers its layer as any mask does, or, when it reaches past the layer, sits over both. An untouched mask crops back to exactly the stored pixels at this rectangle (lossless only while every pixel outside it is still the default color, which a writer checks); its document position is the mask's own origin plus this origin. Import pads a mask only while every mask in the file, as stored plus what padding adds, stays within the mask pixels a project holds (the document pixel budget); a mask it can't pad keeps the stored rectangle as its placement, with no `importedMaskRect`. Missing means the mask's pixels are the stored rectangle itself.
  - `blendingRanges` (base64, up to 4 KiB) and `trailingBytes`, the bytes after the last block in the layer's extra data (base64, up to 64 KiB)
  - `importedText`, `importedTextAnchor`, `importedTextIsBox`, `importedShape`, `importedEffects` and `importedVisible`: what import made of the layer, which a PSD writer compares with the live layer to tell an untouched layer from an edited one. They are never drawn.
  - `importedTextAnchor` (finite x and y) is also where the text is redrawn: Photoshop's first baseline at the alignment point (point text) or box top-left (paragraph text), as a fraction of the layer's own pixels (so it follows moves, scales, rotations and flips). The first time the text is drawn again, the new raster is placed so that its own first baseline or box top-left lands there, and the anchor is removed.
  - `placeholder`, set on a layer kept only to be written back (for example `adjustment:brit`, an adjustment Compositor lacks). Such a layer is hidden and has no pixels.
  - `blocksFile`: the layer's additional-layer-info blocks, in file order, are the sidecar `psd/<layer UUID>.blocks` (at most 64 MiB).
  - `sectionDivider`, on a folder: a nested record of the same fields for the hidden section-divider record Photoshop stores below the folder's contents. Its blocks are `psd/<layer UUID>.divider.blocks`, and it cannot have a divider of its own.
- **Document Photoshop data.** Optional manifest `psd` record:
  - inline: `channelCount` (1–56), `alphaChannelNames`, `iccProfileDescription`, `globalLightAngle` and `globalLightAltitude`, `sourceFileName`, `layerCountNegative`, `linkedBlockIndex` (where the file's linked-layer blocks were among its document-level blocks: the index of the block that followed them, so a PSD save writes its one `lnk2` block back there; absent when the file had none), and `globalLayerMaskInfo` and `colorModeData` (base64, up to 64 KiB each)
  - `resourcesFile`: every image resource in file order is `psd/document.resources` (at most 64 MiB)
  - `blocksFile`: the document-level tagged blocks are `psd/document.blocks` (at most 256 MiB)
  - `linkedFile`: linked-layer entries that no smart object refers to are `psd/document.linked` (at most 512 MiB)
- **Smart objects.** Optional layer `smartObject` and `smartObjectFile`, on a layer that isn't a folder, adjustment, text or shape:
  - `smartObject` holds Photoshop's placed-layer settings: `uniqueID` (`Idnt`, the entry holding the contents; duplicated smart objects share it), `placedID`, the four-character `fileType` (`"png "`, `"8BPB"`, `"PDF "`…, empty when the file had no entry), `fileName`, `naturalSize` and `resolution` of the contents, `placedType` (1 vector, 2 raster), `pageNumber`, `pageCount`, `antiAlias`, `crop`, `contentsRevision` (0 as imported, one more for each replacement), `isEmbedded`, and `link`, the linked-layer entry's other fields as read (`kind` `liFD`/`liFE`/`liFA`, `version`, `creator`, the open-file and linked-file descriptors, timestamp, file size, `childID`, `modTime`, `lockState`, `fileNameNULCount` when the stored file name didn't end in exactly one NUL, and `trailingBytes`, any bytes after the fields the entry's version defines; descriptors and trailing bytes in base64, up to 64 KiB each), so a PSD save writes an untouched entry back byte for byte.
  - `quad`, and `nonAffineQuad` when a perspective makes it differ, are the placement's corners (top-left, top-right, bottom-right, bottom-left) in the unit coordinates of the layer's `transform`: fractions of the layer's own pixel grid, which the transform then places, rotates and flips. The placement is independent of the layer's raster (Photoshop trims transparent margins from the pixels, not from the placement), and because it is stored against the transform, every move, scale, rotation, flip, Canvas Size and Crop carries it. Image Size redraws a turned or flipped layer upright on a new pixel grid, so it re-expresses both quads on that grid: each corner lands where the canvas scale takes it in the document. The corners in document pixels are derived from the transform when a Photoshop file is written.
  - `smartObjectFile` is `{name, sha256}`: the contents are the file `smartobjects/<name>`, where `name` is `<layer UUID>.<extension>` (one to eight lowercase letters and digits), and `sha256` is their SHA-256 in lowercase hex. Layers holding the same contents share one file, named after the first of them, and share the contents again once loaded. A smart object whose contents the file didn't hold (a linked file, or an entry that is missing) has no `smartObjectFile`.
  - Each contents file is at most 512 MiB and all of them together at most 2 GiB; they are not Photoshop sidecars and don't count toward the `psd/` limits. A contents file that is missing, oversized, or whose SHA-256 differs, and a name that is not a layer's, make the project invalid.
  - The layer `psd` record's `importedSmartObject` is the smart object as imported; a writer compares its `uniqueID` and `contentsRevision` to tell untouched contents from replaced ones. Painting, filters and other pixel edits leave the pixels and drop the smart object.
  - The linked-layer blocks themselves (`lnk2`, `lnkD`, `lnk3`, `lnkE`) are never kept in `document.blocks`: their entries are either a layer's smart object or `document.linked`. Version 10 projects saved before smart objects were modeled kept them there; loading one takes the entries out the way a Photoshop import does, placing each smart object against its layer as it is now and recording `linkedBlockIndex`. Import had made pixels of those layers, which may have been painted since, so they get no `importedSmartObject`, and a PSD save writes them as pixels until their contents are replaced.

Sidecars use Photoshop's own wire format:
- a blocks file is a run of tagged blocks, each `signature(8BIM|8B64) key(4) u32 length payload` padded to 2 bytes (4 in `document.blocks`, as Photoshop writes document-level blocks)
- a resources file is a run of image resources, each `signature u16 id` then a padded Pascal name, `u32 length payload`, padded to even
- a linked file is a `lnk2` payload: each entry is a `u64` length and its bytes, padded to 4

Sidecar names must be exactly the ones above, and all of them together are limited to 2 GiB. A sidecar that is missing, oversized, or holds anything but whole blocks, resources or entries (a bad signature, a length past the end, non-zero padding, trailing bytes) makes the project invalid, and it is rejected before the open document is replaced. Saving always writes canonical names, and it writes a sidecar only when there is something to put in it. Undo history, duplicates (which drop the Photoshop layer IDs), Canvas Size, Crop and Image Size carry all of this with the layer.

### Profile adjustments (version 10)

An adjustment layer of kind `Profile` applies a Lightroom or Camera Raw creative profile: an XMP file with `crs:PresetType="Look"`, which carries a LookTable, an RGBTable or both. Its optional `profileSettings` holds:

- `amount`, an integer percent from 0 to 200. 100 is the profile as designed, and it is always 100 for a profile without an Amount.
- An optional `reference` with:
  - `digest`: the SHA-256 of the profile file, 64 lowercase hex characters.
  - `uuid`: the profile's `crs:UUID`, 32 hex characters.
  - `name` and `group`, for display only.

Without a reference, the layer passes its input through.

The profile file itself is stored byte for byte as `profiles/<digest>.xmp`. There is one file per distinct profile, however many layers use it, so a project renders the same on a Mac that doesn't have the profile installed.

Each sidecar must:

- hash to its name;
- be at most 4 MiB;
- be a profile Compositor can apply: output-referred, not restricted to a camera model, and with every table it names embedded.

A project may have at most 256 sidecars, 64 MiB in total. A missing, oversized, mismatched or unusable sidecar makes the project invalid, and it is rejected before the open document is replaced. Unreferenced files in `profiles/` are ignored, and saving writes only the referenced ones.

Files declaring versions 1–9 cannot contain `Profile` adjustments or `profileSettings`, and `profileSettings` is only allowed on a `Profile` layer. Older app builds reject version 10.
